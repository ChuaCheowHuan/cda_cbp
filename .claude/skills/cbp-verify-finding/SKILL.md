# Verify a cda_cbp finding before it costs anything

A claim about Continual Backprop is cheap to make and easy to get wrong: the hooks, the
accumulator and the optimiser slots all have cases a reading misses. Reproduce first.

## Setup (once per container)

gym-CDA is not on PyPI. In a venv: `pip install torch==2.13.0` (the CPU index is faster),
`pip install -e <gym-CDA checkout>`, `git submodule update --init`, then
`pip install -e ".[test]" ruff pyflakes`. `python -m pytest -q` should pass in about 20 s.

## Steps

1. **Restate the claim as a scenario with numbers**: encoder, scope, `fire_on`, minibatch size,
   which layer, what value is wrong and what it should be.
2. **Reproduce it** in a scratch script outside the repository (the session scratchpad), run with
   `python -I`. For anything about what the forward hooks count, run
   `python .claude/skills/cbp-verify-finding/scripts/hook_rows.py` (options `--encoder`, `--scope`,
   `--minibatch`, `--fire-on`): it prints the rows each layer's statistics average over at every
   `_cbp_run`, next to `loss_mask.sum()` per loss call. Rows above the minibatch size mean a forward
   that is not a training step was counted; rows above `loss_mask.sum()` mean padding was counted.
3. **Run the inverse**, a case that should pass, and keep both outputs.
4. **Check it is reachable** from a real config. A layer kind, an activation or a count rule the
   shipped encoders never produce is a lower severity, not a non-issue. `find_replaceable_layers`
   on `build_module(spaces, encoder)` (from `tests/conftest.py`) lists what each encoder exposes.
5. **Classify**: confirmed, false positive, unreachable, already tracked, or cannot reproduce.
   Search the open issues first; a tracked one gets a comment, not a duplicate.
6. **Confirmed, and the task is a fix**: write the regression test first and show it failing on
   the previous source (`git stash push -m <tag> -- cda_cbp`, run, `git stash apply`, then drop
   that entry). One fix per commit: code, then tests, then docs.
7. **Confirmed, and the task is a review**: file it, do not fix it.

## Filing

- Labels: a severity (`S1-blocking` .. `S4-minor`), one of `bug`, `enhancement`, `documentation`,
  `test-gap`, `refactor`, and `agent` (an agent can resolve it alone) or `human` (needs a person: a
  design decision, GPU hardware, a reading of the papers). An issue that needs both is split into
  sub-issues, each labelled; the parent carries both.
- Set the issue type (Bug, Task or Feature) with the issue tool's `type` parameter.
- Say what you ran and paste the raw output; say which parts you only read.
- Link to files, not `#fragment` anchors. End with `_Generated by [Claude Code](https://claude.ai/code)_`.

## Guardrails

- `third_party/loss-of-plasticity` is the authors' code, shipped byte for byte
  (`tests/test_lop.py`). A finding in it is reported upstream, never patched here.
- A rule that exists to match `lop.algos.gnt` (`count_rule: "lop"`) is checked against
  `tests/test_lop_reference.py` before it changes.
